# Spec — GameMaster v5.1.0

## Identity

- **Name:** GameMaster (`worker_clean`)
- **Label:** AI Game Master — text adventures narrated by Claude, built on SISO
- **Version:** 5.1.0 (`VERSION`)
- **Type:** web application (PHP backend + static frontend); not a platform component (no manifest)
- **Language:** PHP ≥ 8.1 (developed on 8.4), ES-module JavaScript frontend; no Composer dependencies
- **Spec compliance:** SISO-principles v1.2 (`doc/SISO-principles.md`) — compliant, see `doc/conformance.md`
- **Core:** PHP port of SISO Canon core v10.0 in `src/Siso/Core`
- **Status:** active
- **Last modified:** 2026-09-28

## Purpose

Players pick a world template and type actions; Claude narrates the result and proposes state changes
(inventory, entities, stats, flags); the game applies the changes it can verify and saves the state.
Worlds: a derelict spaceship, WarGames, the Matrix, and a Portland scavenger hunt with real geography,
game time, money and ten landmarks. Zones can be generated by the AI on demand or ahead of the player.

## Dependencies

- **Runtime:** PHP CLI/FPM with `curl` and `json`. Dev server: `php -S localhost:8080 router.php`.
- **External:** the Anthropic Messages API (key from `../keys.json` or `ANTHROPIC_API_KEY`); without a
  key the mock AI transport answers (`GAMEMASTER_MOCK_AI=true` forces it).
- **Frontend:** none beyond the browser (Google Fonts, optional).

## Architecture in one paragraph

Each HTTP request (or job) becomes **one entry event** emitted into a fresh stream holding all 37 gates.
Gates are pure and routed by event type. A gate that needs something from outside returns a **request
event** that no gate claims — `io_read`, `io_write`, `io_collect`, `ai_call` — so it lands in pending. The
**Driver** (the boundary) samples pending, performs the request, and emits the **reply event whose type
the request named**, carrying the request's `carry` plus the result; that reply causes the next gate.
The flow ends with an **`http_response`** event, which the handler sends. The clock and entropy come in as
data (`now`, `nonce` on entry events; `at` on write replies).

```
HTTP ──▶ handler ──entry event──▶ Stream(gates) ──▶ pending: io_read / io_write / ai_call / io_collect
                                        ▲                                   │
                                        └──── reply event (type named) ◀─ Driver (FileStore, AiTransport)
                                  pending: http_response ──▶ handler ──▶ HTTP
```

## Contracts

### REST API (unchanged for the frontend)

| Method | Path | Entry event | Success | Rejections |
|---|---|---|---|---|
| GET | `/api/templates` | `templates_requested` | 200 `{success, data:[{id,name,theme,description}]}` | — |
| POST | `/api/game/new` `{worldTemplateId?, playerName?, gameId?, overwrite?}` | `game_create_requested` | 201 `{success, message, data:{gameId, worldTemplateId, narrative, currentZone, turnCount:0, player, suggestedActions}}` | 422 validation, 400 bad template / save failed, 409 exists |
| GET | `/api/game/{gameId}[?full=true]` | `game_load_requested` | 200 `{success, data:{gameId, narrative, currentZone, turnCount, player, suggestedActions[, gameState]}}` | 400 bad id, 404 missing/unreadable/corrupt |
| POST | `/api/game/{gameId}/action` `{action}` | `action_submitted` | 200 `{success, data:{narrative, suggestedActions, player, turnCount, currentZone, lastSaved}, error:null, meta:{tokensUsed, turnTokens}}` | 422 validation or in-world failure (same body shape, `success:false`), 400 bad id |
| POST | `/api/action` `{gameId, action}` | `action_submitted` | as above | as above |
| POST | `/api/game/{gameId}/zone/generate` `{zoneId, parentZoneId?, direction?, constraints?}` | `zone_generate_requested` | 201 `{success, message, data: zone}` | 400, 422, 404 game, 409 exists, 500 failed |
| POST | `/api/game/{gameId}/zone/pregenerate` `{fromZoneId}` | `zone_pregenerate_requested` | 200 `{success, message, data:{fromZoneId, requested, generated:[{zoneId,name}], errors:[{zoneId,error}]}}` | 400, 422, 404 |
| GET | `/api/game/{gameId}/zone/{zoneId}` | `zone_get_requested` | 200 `{success, message, data: zone}` | 400, 404 |
| GET | `/api/game/{gameId}/zones` | `zone_list_requested` | 200 `{success, message, data:{gameId, count, zones}}` | 400 |
| DELETE | `/api/game/{gameId}/zone/{zoneId}` | `zone_delete_requested` | 200 `{success, message, data:{deleted}}` | 400, 404, 500 |
| GET | `/api/health` | — (probes in api.php) | 200/503 | — |

Validation errors are `{success:false, error:"Validation failed", errors:{field: message}}`; other errors
`{success:false, error}`.

### Boundary request events (`src/Events/Io.php`)

| Request | Data | Reply data (carry + …) |
|---|---|---|
| `io_read` | `{reads:{name: spec}, reply, carry}` | `reads:{name:{status, data}}`, status ∈ ok, missing, corrupt, unreadable, invalid |
| `io_write` | `{writes:{name: spec+op}, reply, carry}` (op put with content, or delete) | `writes:{name:{ok}}`, `at` |
| `io_collect` | `{types, where, key, expect, reads, reply, carry}` — ready when pending has, for each value in `expect`, an event of `types` matching `where` with `data[key]` = value | `collected:[{type,data}]`, `reads` |
| `ai_call` | `{system, user, reply, carry}` | `ai:{ok, content, usage:{input,output}, model, error:{code,message}\|null}` |
| `http_response` | `{status, body}` | terminal |

Resource specs: `save{gameId}`, `template{templateId}`, `templates{}`, `zone{gameId, zoneId}`,
`zone_index{gameId}`. Ids must match `^[A-Za-z0-9_-]{1,100}\z`; zone id `_index` is reserved.

### Saved game state (`saves/game-{id}.json`)

`gameId, worldTemplateId, created, lastUpdated, turnCount, currentZone, zoneDescription,
player{name, inventory, stats}, entities[{id,name,present,properties}], worldState{day, time,
globalFlags, …}, profile{actionHistory[{turn,action[,time,location]}], observations, patterns},
worldTemplate{theme,tone,worldRules}, budget{sessionTokens, sessionCost, lastTurnTokens}, zones{id:
{name, description, exits, visited, generated}}`; Portland adds `location{name,lat,lng,streetview}`,
`worldState.date`, `worldState.landmarks_visited`, `player.stats.money/landmarks_found`.

## Gates

All gates are pure (P). Flows (⇒ crosses the boundary):

- **Templates:** `templates_requested` → io_read ⇒ `templates_loaded` → 200
- **New game:** `game_create_requested` → io_read{template, existing} ⇒ `game_create_loaded` →
  `game_template_ready` → io_write{save} ⇒ `game_created` → 201
- **Load:** `game_load_requested` → io_read ⇒ `game_load_read` → 200
- **Turn:** `action_submitted` → io_read{save} ⇒ `turn_state_loaded` (classify) → io_read{template} ⇒
  `turn_template_loaded` | `portland_turn_loaded` → ai_call ⇒ `turn_ai_replied` → io_read{save} ⇒
  `turn_apply_loaded` (classify) → `generic_turn_parsed` | io_read{template} ⇒ `portland_turn_parsed` →
  `turn_applied` → `turn_accounted` → io_write{save} ⇒ `turn_saved` → 200; failures → `turn_failed` → 422
- **Zones:** `zone_generate_requested` → io_read ⇒ `zone_generate_loaded` →
  [`zone_target`, io_collect]; `zone_pregenerate_requested` → io_read ⇒ `zone_pregenerate_loaded` →
  [`zone_target` ×N, io_collect]; `zone_target` → ai_call ⇒ `zone_ai_replied` → `zone_parsed` |
  `zone_failed` (pending); io_collect ⇒ `zones_settled` → io_write ⇒ `zone_generate_stored` (201/500) |
  `zone_pregenerate_stored` (200)
- **Zone get/list/delete:** `zone_get_requested` → ⇒ `zone_get_read`; `zone_list_requested` → ⇒
  `zone_list_read`; `zone_delete_requested` → ⇒ `zone_delete_loaded` → io_write{zone delete} ⇒
  `zone_file_deleted` → io_write{index} ⇒ `zone_deleted` → 200

## Tests

Run everything: `php run_tests.php` (`-v` for full output). Each suite also runs standalone
(`php sisoTests/<signature>.test.php`, `php tests/<suite>.test.php`); exit code 0 on pass; final line
`{suite}: {passed}/{total} passed`.

**Gate census** (`php sisoTests/census.php`, this phase): gates: 37, tested: 37, untested: none —
census: 37/37 passed; 147/147 per-gate cases. The census lists gates from `GameStreamFactory`, checks
every class in `src/Gates` is registered, checks each test obtains its gate via `gate('<signature>')`,
runs each file, and checks accepted cases share one output shape (event types, reply types, written
resources, HTTP status; `rejected …` cases excluded, `accepted (class X)` compared per class,
`accepted (empty fan-out)` may be a subset).

Other suites (this phase): siso-core: 35/35 passed · siso-streamlog: 25/25 passed · templates: 4/4 passed ·
scenarios: 18/18 passed (handlers → driver → gates → temp files, scripted mock AI; includes Portland,
inventory guard, budget persistence, zone generate/pregenerate/join/delete, job queue, path traversal).

Test conventions: no PHPUnit, no `assert()`; `tests/runner.php` turns PHP warnings into failures (as
`api.php` does in production). Prompt tests compare against fixtures produced by the pre-port gates
(`sisoTests/fixtures/README.md`). Budget expectations use Anthropic's published prices.

## Known issues

**Moderate**
- Budget limits are not enforced (totals only). Automatic pre-generation after a turn is not wired.
- Pre-generation treats template zones (not in the zone index) as ungenerated.
- Boundary logic outside gates: HTTP router/middleware/health roll-up (B1, B2), job queue state
  transitions and retry scheduling (B3) — see `doc/conformance.md`.

**Minor**
- Portland worlds have no inventory guard. Concurrent requests on one game: last write wins.
- Numeric-looking ids in id-keyed maps are encoded as JSON lists.
- Frontend footer loads `app.js` a second time as a classic script (console error, harmless).
- Tabs in actions are removed rather than collapsed; name `<>` becomes empty; `zones/_queue` vs game id
  `_queue`; `keys.json` is resolved against the working directory.

**Resolved this phase** — see `doc/changelogs/changelog-v5.1.0.md`.
